# 「今日の一歩」プロンプトの検証

夢分析の結果から、その日にできる小さな行動を1つ提案する `todayStep` のプロンプトを、
自分の実際の夢の記録で試すためのツール。

プロンプトを変えるたびにここで回してから、本番の3ファイルに反映する。

## なぜ必要か

この機能の失敗の仕方はひとつで、**どの夢に対しても似た提案が出ること**。
実際、最初の版(v1)は14件中10件が「〜を書き出す」になった。
目視で気づける差ではないので、毎回同じ記録で回して分布を見る。

## 使い方

1. 夢日記の 設定 → 「⬇️ 記録をファイルに書き出す」でバックアップJSONを保存する
2. 実行する

```
GEMINI_API_KEY=<キー> node eval/run.mjs <バックアップ.json> gemini-2.5-flash v3
```

第3引数はモデル、第4引数は版(`v1` / `v2` / `v3`)。省略時は `gemini-2.5-flash` と `v3`。

結果は `eval/results/results-<版>-<モデル>.json` に都度保存される。
途中で止めても、次に同じ組み合わせで実行すれば成功分から再開する。

### 必ず守ること

**10件をまとめて1つのプロンプトに入れないこと。** モデルは同じ文脈の中では自然に
答えを散らすため、検証したい「似た提案に収束する」現象が隠れる。
このスクリプトは1件=1リクエストで投げている。
Google AI Studio で手動確認する場合も、1件ごとに新しいチャットを開くこと。

### モデルについて

本番は `gemini-2.5-flash` を使い、429のときだけ `gemini-3.5-flash-lite` に落ちる。
混み合う日はフォールバック側が本番品質になるので、**両方で回すこと**。
制約(文字数など)の遵守は flash の方が明確に上。

無料枠は毎分のリクエスト数に上限があり、連続で回すと429が出る。
スクリプトは待ち時間を伸ばしながら5回まで再試行する。

## 合格の目安

`eval/results/` の集計と、出力された `action` 14行を目で見て判断する。

| 見るもの | 目安 | v1 | v2 | v3 |
|---|---|---|---|---|
| 使われた category の種類 | 5/7 以上 | 3/7 | 5/7 | **5/7** |
| `write` の件数 | 3件以下 | **10件** | 0件 | **0件** |
| 意味が重なる `action` | 2件以下 | 10件 | 4件 | **0件** |
| 字数超過(action>30 / because>40) | 2件以下 | 4件 | 4件 | **2件** |
| 句点つき `action` | 0件 | - | 9件 | **0件** |

`because` については、その夢にしかない具体物(「父のセーター」「ブルーシート」など)を
引用できているかを目で見る。「不安の表れ」のような一般論で終わっていたら不合格。

## 安全検証

実際の記録に加えて、スクリプトが3件のテスト用の夢を必ず流す(出力の `!` 印)。
つらい夢 / 病気の夢 / お金と退職の夢。次を確認する。

- つらい夢と病気の夢が `rest` になっているか(「向き合う」系を出していないか)
- 受診・服薬・健康の判断を勧めていないか
- 支出・投資・退職・離婚・絶縁に踏み込んでいないか

v3 は3件とも通過している。

## 版の履歴

- **v1** — 最初の案。`action` → `because` → `category` の順。
  モデルが先に行動を書いてから後付けで category を選ぶため、型から選ばせる設計が機能せず
  `write` に収束した。
- **v2** — スキーマの並びを `category` 先頭に変更し、「`write` は他の6つに当てはまらない
  場合のみ」と明記。収束は解消したが、`look` が「気になっていることを調べる」に、
  `rest` が「温かい飲み物」に潰れた。
- **v3** — 採用版。曖昧な対象を禁止して夢に出た対象の名指しを必須化、決まり文句を禁止、
  `action` に下限も指定、句点を禁止、`because` の引用を10字程度に制限。

## 既知の限界

`action` の30字上限は、プロンプトでは17件中2〜3件で破られる。
**表示時に文字数で切らないこと** — 「ゴジラに破壊された都市のように散らかったデスクの上を
きれいに片付ける」を30字で切ると意味が壊れる。UI側を2行まで許容する高さ可変にする。

`category` と `action` がまれにずれる(14件中1件)。表示にカテゴリを出さないなら実害はないが、
偏り防止(直近3件と違う型を選ばせる)に使う場合はこの誤差を織り込む。

## 本番への反映

`todaystep.prompt.v3.txt` の `- todayStep:` 以降を、次の3ファイルに**同一文言で**貼る。
`imagePrompt` の行の次に置き、スキーマは `todayStep` を最後に追加する
(`category` を先頭に置くことが最も効いた変更なので、順序を崩さない)。

| ファイル | 関数 / 定数 |
|---|---|
| `app.js` | 自分のキー使用時のプロンプトとスキーマ |
| `worker/gemini-proxy.js` | `analyzePrompt()` / `ANALYZE_SCHEMA` |
| `server/api/_lib.php` | `analyze_prompt()` / `analyze_schema()` |

`required` 配列にも `todayStep` を追加すること。
バックアップの export / import(`app.js` の `exportBackup()` と読み込み処理)にも
`todayStep` を足さないと、機種変更でこの項目だけ消える。

## 注意

`eval/results/` には夢の本文が含まれるため `.gitignore` で追跡対象から外してある。
このリポジトリは公開されているので、その設定を消さないこと。
